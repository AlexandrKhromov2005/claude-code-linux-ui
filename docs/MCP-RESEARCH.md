# Исследовательские MCP-серверы (веб-ресёрч)

Клиент умеет подмешивать пользовательские MCP-серверы в **агентный режим**, чтобы
Claude мог искать в интернете и читать страницы (Brave, Tavily, Exa, Perplexity,
keyless-`fetch` и т.п.) — рядом со встроенным permission-сервером и через ту же
модалку approve/deny.

## Как включить

1. Скопируй шаблон `docs/mcp.example.json` в конфиг-директорию под именем `mcp.json`:

   ```
   ~/.config/claude-code-linux-ui/mcp.json
   ```

   (Если задан `XDG_CONFIG_HOME` — то `$XDG_CONFIG_HOME/claude-code-linux-ui/mcp.json`.)

2. Оставь только те серверы, для которых у тебя есть ключи, и подставь ключи в `env`.
   Формат файла — тот же `mcpServers`, что понимает `claude --mcp-config`, поэтому
   любую запись можно взять из документации соответствующего сервера как есть.

3. Перезапусти клиент (`serve` или TUI). Файл читается один раз при старте.

4. В разговоре переключись в **agent** (`Tab` / `Ctrl+G` или `/mode agent`) и попроси
   что-нибудь найти. Первый вызов веб-инструмента придёт в модалку approve/deny —
   можно нажать «запомнить», чтобы дальше не спрашивал.

## Что за серверы в шаблоне

| Имя          | Команда                                    | Ключ               | Заметка |
|--------------|--------------------------------------------|--------------------|---------|
| `fetch`      | `uvx mcp-server-fetch`                      | не нужен           | тянет содержимое URL; нужен `uv`/`uvx` |
| `brave-search` | `npx -y @modelcontextprotocol/server-brave-search` | `BRAVE_API_KEY`    | веб-поиск |
| `tavily`     | `npx -y tavily-mcp`                         | `TAVILY_API_KEY`   | поиск + извлечение |
| `exa`        | `npx -y exa-mcp-server`                     | `EXA_API_KEY`      | нейропоиск |
| `perplexity` | `npx -y server-perplexity-ask`             | `PERPLEXITY_API_KEY` | ответы с источниками |

Точные имена npm/uvx-пакетов и набор env-переменных сверяй с актуальной докой каждого
провайдера перед тем как полагаться на запись — они меняются. Для stdio-серверов нужен
установленный рантайм (`npx` из Node, `uvx` из uv).

## Безопасность

- Серверы из `mcp.json` **не могут** переопределить встроенный `permctl`: запись с
  именем `permctl` игнорируется.
- Веб-инструменты доступны только в **agent**-режиме и проходят через approve/deny —
  как любой другой инструмент. В `chat` (read-only) они не подключаются: чат остаётся
  без внешних вызовов. Включение ресёрча прямо в `chat` затрагивает модель
  безопасности (chat = без внешних вызовов), поэтому сознательно не делалось молча —
  это отдельная фаза, требующая согласования.
- stdio-серверы запускаются как дочерние процессы `claude`; ключи берутся из `env`
  записи и в транскрипт не попадают.

## Что под капотом

`internal/core/mcp.go` читает `mcp.json` и сливает его `mcpServers` в тот же
`--mcp-config`, который клиент и так строит для permission-сервера
(`Engine.ExtraMCP` → `mergeMCPConfig`). Никаких новых зависимостей; в `chat`-режиме
поведение не изменилось.
